## Post-test reporting bug, not an experimental alteration
The first `src/finalize.py` run failed at the per-block count assertion after creating the per-cycle audit vectors: selector `(cycle//6==block or (cycle-1)//6==block)` erroneously double-counted the boundary cycle of the previous block, producing 7 instead of 6. Corrected to `(cycle-1)//6==block`. There were no changes to the frozen forecast engine, preregistered comparisons, validation, final predictions or test results. This script is an after-the-fact adversarial audit, not a preregistered model. The failed version is described, and the corrected version is versioned in the ZIP.
